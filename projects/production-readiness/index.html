01 · Problem

Production readiness discussions need evidence, not checkbox confidence.

A deployment can succeed while recovery, supply-chain controls and operational ownership remain unproven.

I built the assessment engine to evaluate an explicitly authorized repository without connecting to networks, clusters, cloud accounts, registries, identity systems or databases. The target is mounted read-only and only the report directory is writable.

The engine applies a profile appropriate to the target—application, GitOps platform or infrastructure—so repositories are assessed against relevant controls rather than a universal checklist.

03 · Control model

One evidence model, adapted to the system under review.

Delivery

CI/CD governance

Build, test, security validation, artifact publication and promotion controls are evaluated from repository evidence.

Supply chain

Artifact integrity

Dependency locking, image immutability, SBOM generation, vulnerability gates, signing and attestation.

Kubernetes

Workload safeguards

Identity, privilege, resource governance, probes, network boundaries and immutable image references.

Operations

Observability and SLOs

Telemetry, actionable alerting, service objectives, incident ownership and operational runbooks.

Recovery

Restore evidence

Backup automation, encryption, retention, recovery objectives and proof that restoration has been tested.

Governance

Owned exceptions

Accepted risk retains original evidence and requires an accountable owner, rationale and expiry date.

05 · Safety and integrity

The assessment boundary is an engineering feature.

Passive by design

No target connectivity

No network discovery, cloud login, cluster access, registry access or database connection is performed.

Reproducible runtime

Container-first operation

The reviewed non-root image contains pinned runtime and reporting dependencies while client evidence remains read-only.

Evidence integrity

Verify before delivery

Manifests record SHA-256 hashes, byte sizes, tool version and immutable image identity; optional Ed25519 signatures support independent verification.
